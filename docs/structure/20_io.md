# 20. `io/` 目录

## 20.1 目录职责

`io/` 负责把“真实设备”抽象成代码接口。算法层只关心“拿到图像、姿态、控制接口”，不需要直接处理 SDK、串口重连、CAN 回调、ROS2 节点生命周期。

## 20.2 顶层文件

| 文件 | 作用 |
| --- | --- |
| `io/CMakeLists.txt` | 定义 `io` 静态库，串起相机 SDK、串口库、ROS2 可选源码。 |
| `io/camera.hpp` | 相机统一抽象 `CameraBase` 和工厂式包装类 `Camera`。 |
| `io/camera.cpp` | 根据 YAML 中的 `camera_name` 选择 `MindVision` 或 `HikRobot`。 |
| `io/cboard.hpp` | C 板 CAN 通信接口，定义 `Mode`、`ShootMode` 和 `CBoard`。 |
| `io/cboard.cpp` | 解析 CAN 帧、插值 IMU 四元数、发送控制指令。 |
| `io/command.hpp` | 视觉侧统一控制命令结构 `io::Command`。 |
| `io/socketcan.hpp` | Linux SocketCAN 封装，包含 epoll 读取和守护线程重连逻辑。 |

## 20.3 `io/gimbal/`

| 文件 | 作用 |
| --- | --- |
| `io/gimbal/gimbal.hpp` | 串口云台协议结构、状态结构、接收统计结构、`Gimbal` 类声明。 |
| `io/gimbal/gimbal.cpp` | 串口打开、收发包、CRC 校验、姿态插值、重连。 |

### 核心函数

- `Gimbal::q(t)`：从接收队列取前后两帧四元数并做球面插值。
- `Gimbal::send(...)`：发送视觉到云台的控制包。
- `Gimbal::read_thread()`：后台读取线程，负责协议解析、统计和状态刷新。
- `Gimbal::reconnect()`：错误过多时的串口重连。

## 20.10 关键数据结构

- `io::Command`：视觉输出给下位机的统一命令，字段最少，适合作为算法层公共返回值。
- `io::GimbalToVision`：下位机到视觉的扩展串口包，包含姿态、速度、odom 和机器人 ID。
- `io::VisionToGimbal`：视觉到下位机的串口包，包含 `tracking/pitch/yaw/fire/fric_on`。
- `io::GimbalState`：上层读取的云台状态快照。
- `io::GimbalRxStats`：串口接收质量统计，用于诊断掉包/CRC 错误。
- `io::CBoard::IMUData`、`io::DM_IMU::IMUData`：时间戳对齐后的四元数缓存节点。

## 20.11 这一层对上层的价值

- `tasks` 不需要知道相机 SDK 差异，只调用 `Camera::read`。
- 主程序不需要自己做姿态插值，只调用 `Gimbal::q` 或 `CBoard::imu_at`。
- 调试程序不需要自己处理串口掉线，只复用 `Gimbal::read_thread/reconnect`。
